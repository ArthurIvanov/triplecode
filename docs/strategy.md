# Стратегия TripleCode после аудита зрелости

**Статус** — принято 25 ноября 2026 года.  
**Решение о базе:** [ADR 0004](adr/0004-continue-vs-rewrite.md) — эволюционируем текущую базу, не начинаем IDE с нуля.  
**Срез зрелости:** [maturity-assessment.md](maturity-assessment.md).

## Цель на горизонте

Дать пользователю VS Code-привычный редактор с тем же классом локальных AI-задач, что Cursor (Ask → Plan → Agent → diff → checks), при дифференциации **verify-before-accept**. Паритет с Devin (облачная автономия, PR, изоляция) — отдельный Stage 3 после стабильного локального runtime.

Позиционирование на пилот и бету: не «полный аналог Cursor+Devin завтра», а **проверяемый агент в знакомой IDE**. Карта паритета в [product-plan.md](product-plan.md) остаётся обязательством по этапам.

## Архитектурная правда

| Сейчас | Цель |
| --- | --- |
| Repackage pinned VSCodium + Workbench JS/CSS patches + `triplecode-mvp` | Source fork Code-OSS с регулярным merge, когда сработают триггеры ADR 0002 / 0004 |
| AI = extension host + webview, single-shot LLM + текстовый протокол правок | AI runtime: streaming, tool-calling, MCP, индекс контекста |
| Нет `triplecode-web` / CI артефактов | Два репозитория по [repositories.md](repositories.md), CI и манифест релизов |

Подробности текущего устройства — в [architecture.md](architecture.md).

## Критический путь (порядок, не меню опций)

### Волна A — закрыть Stage 1 и пилот

1. Поднять `triplecode-web`: кабинет, квоты, учёт AI по контракту из [accounts.md](accounts.md).
2. Довести ручную приёмку Review (per-file Keep/Drop, Check patch, Undo) и E2E импорта реального профиля.
3. Починить source-of-truth документы (обрезанные файлы, расхождение «форк» ↔ repackage).
4. Не менять продуктовый wedge и не открывать внешний пилот без аккаунта/подписки.

**Выход:** ≥80% пилотных участников завершают импорт + первую AI-задачу без помощи (критерий Stage 1 в product-plan).

### Волна B — инженерный пол

1. CI: сборка macOS из `scripts/build-macos.sh`, проверка checksum/патч-якорей, `tsc` webview.
2. Smoke на agent: stop / apply / undo / Ask не пишет файлы.
3. Разбить и типизировать host-логику `extensions/triplecode-mvp` (сейчас монолит `extension.js`).
4. Версионировать UI-check harness в репозитории или документированный артефакт CI — не только в gitignored `.triplecode-dev`.

**Выход:** воспроизводимая сборка и регрессия P0 без ручного шаманства на одной машине.

### Волна C — AI platform floor (бета-паритет Cursor desktop)

Порядок внедрения:

1. Streaming ответов в Agents UI.
2. Tool-calling loop (чтение/запись/терминал checks как инструменты модели) вместо одного текстового протокола.
3. MCP host с явными разрешениями пользователя.
4. Индекс / быстрый поиск контекста + нормальный `@` picker в composer.
5. Cmd-K (edit from selection) и включение Tab после модели автодополнения.

**Выход:** строки беты карты паритета по agent/tools/context/inline закрыты критериями приёмки, не наличием кнопки.

### Волна D — release floor

1. Подписанные сборки macOS; затем Windows x64 и Linux x64.
2. Канал обновлений и откат по манифесту ([repositories.md](repositories.md)).
3. Решение о переносе layout с minified-патча на исходники, если пороги ADR 0002 достигнуты или merge слишком дорог.

**Выход:** критерии Stage 2 product-plan.

### Волна E — Devin-класс (полный релиз)

Только после A–D и измерения стоимости локальной задачи:

1. Изолированные рабочие копии / окружения.
2. Фоновые и облачные сессии с продолжением после закрытия IDE.
3. Доставка PR и командный handoff с историей проверок.
4. Командные квоты, аудит, эксплуатационные метрики.

**Выход:** Stage 3 product-plan. До волны E не обещаем «как Devin» во внешних коммуникациях.

## Что сохраняем без переписывания

- Verify-first Review и история проверок.
- Импорт профиля VS Code и Open VSX-пилот.
- Hybrid Ollama + BYOK на Stage 1.
- ADR 0001–0003 и роли в `AGENTS.md`.

## Что явно откладываем

| Тема | До когда |
| --- | --- |
| Собственный shell / отказ от Code-OSS | Не рассматриваем |
| Agents Window как второе полное окно | После доказанной потребности в multi-task (competitive audit) |
| Marketplace Microsoft | Вне политики MVP/беты |
| Собственный inference как единственный путь | После прозрачного учёта; MVP остаётся BYOK + local |
| Полный rewrite `triplecode-mvp` | Только модульная эволюция и TypeScript migration |

## Метрики успеха стратегии

| Горизонт | Метрика |
| --- | --- |
| Пилот | Доля завершивших импорт + первую задачу; медиана ≤15 мин; нет потери профиля |
| Бета | ≥95% приоритетной матрицы; crash-free ≥99,5%; откат обновления на каждой ОС |
| AI quality | Доля принятых после checks; медиана времени Review; откаты за 24 ч; стоимость принятой задачи |
| Архитектура | Число Workbench-замен и подсистем (ADR 0002); стоимость upstream bump в человеко-днях |

## Следующее конкретное действие

Владелец продукта закрывает волну A.1 (`triplecode-web` кабинет/квоты) как блокер пилота; параллельно инженер IDE ведёт волну B (CI уже в `.github/workflows`, дальше — smoke сценариев и модульность extension). Детальный backlog: [roadmap.md](roadmap.md). Сценарии: [scenarios/](scenarios/).
