# 0002. Патч компоновки Workbench для MVP

**Статус** — принято для MVP, 22 ноября 2026 года.

## Контекст

TripleCode требует компоновку: Explorer слева, редактор по центру, AI справа (Secondary Side Bar), терминал под редактором (Panel bottom) и **терминал не должен заходить под правую панель AI**.

Штатные возможности Workbench:
- Secondary Side Bar достижима через `workbench.secondarySideBar.defaultVisibility`
- Позиция Panel достижима через `workbench.panel.defaultLocation`
- Однако структура сетки Workbench помещает Secondary Side Bar **за пределами** ветки editor+panel
- При штатной компоновке Panel (bottom) занимает всю ширину под editor+panel, заходя под Secondary Side Bar

## Рассмотренные варианты

| Вариант | Плюсы | Минусы |
| --- | --- | --- |
| Штатные настройки | Нет патча, лёгкий merge upstream | Терминал заходит под AI — нарушает требование |
| Минимальный патч сетки | Решает обязательную перестановку, контролируемый diff | Требует пересмотр при обновлении upstream |
| Полный патч (текущий) | Максимум контроля, единое место изменений | Больше замен в JS |
| Отдельный Workbench | Минимальные изменения в основном IDE | Два окна, больше работы по синхронизации |

## Решение

Принять **минимальный патч сетки** для MVP:
- Сохранить framed layout через grid spacers (`triplecode.gutter`) — обязательно для геометрии
- Переместить размеры частей в `configurationDefaults` где возможно
- Оставить Title Bar команды и кастомные иконки — часть функционала TripleCode

Текущий патч в `apply-workbench-layout.py`:
- 17 замен в `vs/workbench/workbench.desktop.main.js`
- 1 файл CSS добавляется
- Проверка на SHA `c072cf642cbbadabefa22f39c58cc902a8b7427f`

## Последствия

### Положительные
- Терминал не заходит под AI — соответствует требованиям ide-design.md
- Контролируемый diff, привязанный к конкретному SHA upstream
- Визуальный стиль TripleCode (рамки, иконки, типографика)

### Отрицательные
- При каждом обновлении upstream требуется пересмотр патча
- Если количество замен значительно увеличится — пересмотреть границу форка

## Условия пересмотра

Пересмотреть глубину форка если:
- Количество замен в сетке > 30
- Патч затрагивает более 2 подсистем
- Нарушается восстановление состояния или совместимость расширений

При выполнении критерия рассмотреть:
- Отдельный агентский Workbench по образцу `vs/sessions`
- Повседневное окно редактора на чистом upstream
- AI-задачи в отдельном окне с собственным Workbench
