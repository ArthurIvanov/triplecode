# 0004. Продолжать текущую базу, не начинать IDE с нуля

**Статус** — принято, 25 ноября 2026 года.

## Контекст

Аудит зрелости (25.11.2026) показал: TripleCode — рабочий закрытый macOS-MVP с agent-loop Ask/Plan/Agent → Review → checks, но не форк Code-OSS в дереве репозитория и не AI-платформа уровня Cursor/Devin. Объём собственного кода невелик (~5–6k LOC + скрипты упаковки). Возник вопрос: выбросить базу и начать заново или доводить то, что есть.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы |
| --- | --- | --- |
| Полный rewrite IDE с нуля (свой shell / новый стек) | Чистый старт без legacy-патчей | Потеря VS Code-паритета, импорта профилей, Extension Host; месяцы без продукта |
| Выбросить `triplecode-mvp` и писать AI-слой заново | Чище типы и модули | Потеря проверенного P0 UX (stop, plan, review, checks); повторная приёмка с нуля |
| Продолжать как есть без смены модели сопровождения | Быстрые фичи | Патчи минифицированного Workbench и монолит `extension.js` упрутся в потолок до беты |
| **Эволюция текущей базы** с явными триггерами перехода на source-fork и AI runtime | Сохраняет продукт и wedge; закрывает долг по плану | Нужна дисциплина не раздувать JS-патчи и не обещать Devin до Stage 3 |

## Решение

**Не начинать проект заново.** Сохраняем и развиваем:

1. Дистрибуцию на VSCodium (ADR 0001) до триггера перехода на дерево исходников.
2. Минимальный патч Workbench (ADR 0002) в пределах его порогов пересмотра.
3. Расширение `extensions/triplecode-mvp` как носитель продукта: Review-first agent, импорт профиля, аккаунт.
4. Продуктовый wedge «каждое изменение AI можно проверить до принятия» и карту паритета в `docs/product-plan.md`.

**Не делаем:**

- Новый редактор поверх одного Monaco.
- Параллельный «чистый» AI-клиент вместо текущего Agents panel до закрытия Stage 1 пилота.
- Cloud/Devin-слой до стабильного локального runtime, учёта стоимости и изоляции (Stage 3).

Переход к **source-level форку Code-OSS** — плановая эволюция, не rewrite продукта. Триггеры: пороги ADR 0002 (>30 замен или >2 подсистем), либо публичная бета с регулярным upstream merge, либо невозможность реализовать обязательный UX без исходников. Детали очередности — в [docs/strategy.md](../strategy.md).

## Последствия

### Положительные

- Сохраняется уже проверенный macOS P0 и путь миграции с VS Code.
- Документы и ADR остаются каноном; стратегия уточняет правду «repackage сейчас → fork по триггеру».
- Инженерные вложения идут в AI runtime, CI и `triplecode-web`, а не в повтор shell.

### Отрицательные / риски

- Пока нет `src/vs/`, каждый bump VSCodium остаётся риском для layout-патча.
- Монолит `extension.js` нужно модулировать и типизировать без остановки фич.
- Искушение «ещё один патч в minified JS» должно отсекаться порогами ADR 0002.

## Условия пересмотра

- Патч Workbench превысил пороги ADR 0002 и блокирует бета-релиз.
- Пилот показал, что extension-only AI не даёт сопоставимого с Cursor перехода edit → agent.
- Появилась команда/бюджет на полноценный fork раньше, чем на закрытие пилота — тогда fork поднимаем параллельно, продукт не выбрасываем.
