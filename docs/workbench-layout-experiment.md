## Целевая компоновка (по ide-design.md)

Explorer слева, редактор по центру, AI справа (Secondary Side Bar), терминал под редактором (Panel bottom).

## Штатные возможности Workbench (по upstream docs)

### Secondary Side Bar
- Штатная поддержка через `workbench.secondarySideBar.defaultVisibility`
- Позиция всегда противоположна Primary Side Bar
- Toggle через `View: Toggle Secondary Side Bar Visibility` (⌥⌘B)
- Настройка видимости в пустом workspace: скрыт по умолчанию

### Primary Side Bar
- Позиция: `workbench.sideBar.location` (left/right)
- Toggle через `View: Toggle Primary Side Bar Position`

### Panel
- Позиция: `workbench.panel.defaultLocation` (bottom/left/right)
- Максимизация: `workbench.panel.opensMaximized` (never/always/remember)

### Layout Controls
- Команды в Title Bar для переключения панелей
- Настройка видимости через `window.commandCenter`

## Классификация изменений

### Уровень 1: Штатные настройки (без патча)

Достижимо через `configurationDefaults` в package.json:
- `workbench.secondarySideBar.defaultVisibility: "hidden"` → изменено на видимость
- `workbench.sideBar.location: "left"`
- `workbench.panel.defaultLocation: "bottom"`
- `workbench.panel.opensMaximized: "never"`
- Цветовая тема через `workbench.colorCustomizations`

**Результат:** Базовая компоновка achievable, но без кастомных пропорций и рамок.

### Уровень 2: Точки расширения (минимальный патч)

Достижимо через contribution points:
- `viewsContainers.secondarySidebar` для AI-панели (уже используется)
- `commands` для кнопок в Title Bar (частично achievable через `menus.titleBar`)
- Кастомные CSS через веб-расширение (ограниченно)

**Ограничения:**
- Title Bar команды ограничены штатным набором
- CSS не может менять топологию сетки
- Размеры частей ограничены дефолтными настройками

### Уровень 3: Патч Workbench (текущий подход)

Текущий патч затрагивает:
- **17 замен** в workbench.desktop.main.js
- **1 файл CSS** добавляется
- **Сетка Workbench** (SerializableGrid)
- **Размеры частей** (инициализация layout service)
- **Title Bar** (добавление команд)

**Влияние на upstream:**
- При каждом обновлении upstream требуется пересмотр патча
- Риск конфликтов при изменении структуры Workbench
- Требуется проверка на каждом SHA

## План эксперимента

### Шаг 1: Базовая компоновка без патча

Создать тестовый бандл без применения `apply-workbench-layout.py` и проверить:
1. Отобразить Secondary Side Bar справа
2. Разместить Explorer слева
3. Разместить Panel снизу
4. Проверить перестановку разделителей
5. Проверить восстановление после перезапуска

### Шаг 2: Обязательная перестановка

Если базовая компоновка работает, воспроизвести перестановку, которая НЕ достижима штатными средствами:
- **Цель:** терминал под редактором, но не заходящий под правую панель AI
- **Проблема:** штатная сетка Workbench может иметь ограничение на геометрию

Если это требование НЕ достижимо штатно — требуется патч сетки.

### Шаг 3: Оценка патча сетки

Если патч обязателен:
1. Замерить количество изменённых upstream-файлов
2. Проверить поведение фокуса и восстановления
3. Проверить работу представления стороннего расширения
4. Перенести патч на соседний стабильный тег для проверки стоимости merge

## Критерии решения

| Результат | Решение |
| --- | --- |
| Базовая компоновка достижима штатно + перестановка не нужна | Убрать патч сетки, использовать настройки |
| Базовая компоновка достижима, но нужна обязательная перестановка → небольшой diff (менее 5 замен в сетке) | Поддержать патч как явное изменение форка |
| Патч затрагивает несколько подсистем или ломает восстановление | Рассмотреть отдельный агентский Workbench по образцу `vs/sessions` |

## Результаты эксперимента

### Шаг 1: Базовая компоновка без патча

Собран бандл `dist/TripleCode.app` без патча Workbench. Настройки:
- `workbench.secondarySideBar.defaultVisibility: "visible"`
- `workbench.sideBar.location: "left"`
- `workbench.panel.defaultLocation: "bottom"`

**Результат:** Базовая компоновка достижима штатно. Explorer слева, Editor по центру, Secondary Side Bar справа, Panel снизу.

### Шаг 2: Обязательная перестановка

**Проблема:** По upstream документации и issue #248807, структура сетки Workbench имеет ограничение:
- Secondary Side Bar находится **за пределами** ветки editor+panel в сетке
- Panel (bottom) занимает всю ширину под editor+panel веткой
- При штатной компоновке терминал **заходит под правую панель AI**

**Требование по ide-design.md:** "Терминал располагается под редактором и не заходит под правую панель"

**Вывод:** Эта перестановка **НЕ достижима штатными средствами**. Требуется патч сетки.

### Шаг 3: Оценка патча сетки

Текущий патч в `apply-workbench-layout.py`:
- Добавляет grid spacers (`triplecode.gutter`) — фиксированные рамки вокруг частей
- Меняет топологию сетки с "framed layout" — разделяет части рамками
- 17 замен в workbench.desktop.main.js
- 1 файл CSS добавляется

**Изменённые upstream-файлы:**
- `vs/workbench/workbench.desktop.main.js` (патч)
- `vs/workbench/workbench.desktop.main.css` (добавление)

**Классификация:**
- **Сетка Workbench** — обязательная часть патча (raming)
- **Размеры частей** — можно переместить в настройки (опционально)
- **Title Bar команды** — часть функционала TripleCode (обязательна)
- **Кастомные иконки** — визуальный стиль (опционально для MVP)

### Минимизация патча

Возможные варианты:

1. **Полный патч (текущий)** — всё в одном месте, максимум контроля
2. **Минимальный патч** — только сетка для framed layout, остальное через настройки
3. **Отдельный Workbench** — новый агентский Workbench по образцу `vs/sessions`

## Рекомендация

Для MVP выбран **минимальный патч сетки**:
- Сохранить framed layout через grid spacers (обязательно для геометрии)
- Переместить размеры частей в `configurationDefaults` (если возможно)
- Оставить Title Bar команды и кастомные иконки (часть функционала)

**Обоснование:**
- Framed layout решает обязательную перестановку (терминал не заходит под AI)
- Размеры частей через настройки упрощают патч и дают пользователю контроль
- Title Bar команды и иконки — часть продукта, не могут быть штатными

**Стоимость merge:**
- При каждом обновлении upstream требуется пересмотр 17 замен в JS
- Проверка на SHA `c072cf642cbbadabefa22f39c58cc902a8b7427f` уже есть
- Если количество замен значительно увеличится на следующем SHA — пересмотреть границу форка

## Альтернатива: Отдельный Workbench

Если патч станет слишком громоздким (>30 замен или затронет несколько подсистем), рассмотреть:
- Отдельный агентский Workbench по образцу `vs/sessions`
- Повседневное окно редактора остаётся на чистом upstream
- AI-задачи открываются в отдельном окне с собственным Workbench

**Плюсы:**
- Минимальные изменения в основном IDE
- Изоляция AI-функционала
- Легче обновлять upstream

**Минусы:**
- Два окна вместо одного
- Не соответствует "единая история контекста" из позиционирования
- Больше работы для синхронизации состояния

## Решение для MVP

**Принять минимальный патч сетки** (текущий подход с потенциальной минимизацией).

**Критерий пересмотра:**
- Количество замен в сетке > 30
- Патч затрагивает более 2 подсистем
- Нарушается восстановление состояния или совместимость расширений

**Действия:**
1. Оставить текущий патч как есть для MVP
2. При следующем обновлении upstream оценить возможность минимизации
3. При критерии пересмотра — рассмотреть отдельный Workbench
