В репозитории есть первый рабочий срез для Workbench. Его можно запустить отдельно от основного профиля редактора.

## Самостоятельная сборка MVP для macOS

На Apple Silicon из корня репозитория:

```bash
./scripts/build-macos.sh
open dist/TripleCode.app
```

Скрипт проверяет SHA-256 закреплённого архива VSCodium, собирает React-панель, встраивает расширение TripleCode в бандл, задаёт собственный ID приложения и подписывает бандл локальной ad hoc подписью. Бандл запускается без установленного VS Code. Для сборки требуются macOS, Python 3, Node.js с npm и сеть для загрузки архива и зависимостей при отсутствии кеша. Сборка предназначена для локальной проверки. Публикация потребует отдельной подписи и нотарификации.

1. На экране Welcome нажмите **Open project** и выберите локальную папку с файлом TypeScript или JavaScript.
2. Откройте файл в Explorer. Выполните **TripleCode: Open Agent** из палитры или нажмите **Agents** в заголовке редактора.
3. Введите `Add a comment: MVP preview` и нажмите **Send**. В правой панели появится предпросмотр. Нажмите **Review**, чтобы открыть штатный diff.
4. Нажмите **Apply changes** и сохраните файл. **Discard** оставляет исходный текст без изменений.

Панель агента открывается в правой боковой области Workbench. Терминал находится под основным редактором. Патч генерируется локальным правилом. SSH отображается как недоступное действие. Для разработки расширения установите зависимости командой `npm --prefix extensions/triplecode-mvp ci`, затем запустите `./scripts/run-mvp.sh`. Скрипт собирает webview перед запуском расширения.

### Запуск QA на macOS

После сборки запускайте обычные smoke- и UI-тесты через `./scripts/run-macos-qa.sh [путь-к-проекту]`. Этот запуск использует тестовую связку Electron и профиль `.triplecode-dev/qa`. Используйте в этом профиле только тестовые данные.

Для проверки системного Keychain соберите и запустите отдельное QA-приложение.

```bash
./scripts/build-macos.sh --keychain-qa
./scripts/run-macos-qa.sh --real-keychain
```

У приложения постоянные имя `TripleCode Keychain QA` и bundle ID `com.tripleform.triplecode.keychain-qa`. При первом запросе macOS выберите **Always Allow**. Для повторных прогонов используйте уже собранный бандл. Если требуется сохранять разрешение между пересборками, задайте одну и ту же действительную подпись через `TRIPLECODE_QA_SIGNING_IDENTITY`. При ad hoc подписи macOS может повторно запросить доступ после изменения сборки.
