# Правила дизайн-системы TripleCode

Эти правила дополняют [AGENTS.md](../AGENTS.md) и [правила разработки IDE](../docs/engineering.md). Архитектор дизайн-системы ведёт задачи по общим компонентам, токенам и синхронизации с Figma. В задаче или PR фиксируются исходный узел, затронутые поверхности, критерии приёмки и результаты проверки.

## Порядок работы

1. Изучи текущий компонент, его точки входа, соглашения API и существующие токены. Для работы по макету получи через Figma MCP структуру, скриншот, привязки Variables и доступные режимы. Запись в Figma выполняй в рамках порученной правки.
2. Сопоставь варианты, значения по умолчанию, содержимое, размеры и интерактивные состояния. Расхождения между дизайном и реализацией фиксируй с указанием поверхности и темы. Для технического примитива без макета опиши контракт и сценарии.
3. Используй существующие адаптеры, компоненты, CSS и механизмы Code OSS. Сравнивай с внешними дизайн-системами, когда нужно разрешить конкретную неопределённость API, доступности или композиции. Запрос на реализацию разрешает изменения в репозитории в указанном объёме. Если запрос ограничен прототипом, держи работу в предпросмотре до поручения интеграции.
4. Для нового общего компонента добавь пример в существующую галерею, когда он помогает проверить варианты. Проверяй фактическую точку входа, размеры, состояния, загрузку ассетов, доступное имя, клавиатуру и фокус. Если результат предназначен для desktop-сборки, проверь упакованное приложение и открытие галереи через штатную команду. Указывай фактически проверенную среду и пропуски.

## Темы и токены

- Сопоставляй цвет по назначению, например фон наведения или контур фокуса. Для интерфейса, который следует теме IDE, используй семантические `--vscode-*` как основной источник цветов. Брендовые и структурные значения Webview бери из `media/tokens.css` там, где требуется локальный токен. Проверяй каскад Workbench и Webview отдельно, поскольку глобальные переопределения могут перекрывать значения активной темы.
- Предпросмотр с фиксированной палитрой Figma используй для сравнения макета. Совместимость рабочего компонента проверяй отдельно в светлой, тёмной и кастомной теме. Высококонтрастные режимы проверяй для контролов, у которых меняются границы или индикатор фокуса.
- Если требуемого значения нет в токенах или варианте Figma, укажи пробел и источник принятого значения. Общий токен добавляй в правильный слой и учитывай существующих потребителей.

### Каскад темы в коде

- [figma-tokens.css](../extensions/triplecode-mvp/media/figma-tokens.css) хранит экспорт Light и Dark и общую шкалу отступов.
- [theme-bridge.css](../extensions/triplecode-mvp/media/theme-bridge.css) задаёт алиасы вида `--triplecode-theme-editor-background`. Алиас сначала читает `--vscode-editor-background`, затем использует резервное значение Figma. Подключай слой через `tokens.css` в Webview. Desktop-сборка включает его в CSS Workbench.
- В [конфигурации расширения](../extensions/triplecode-mvp/package.json) палитры Figma заданы для Dark Modern и Light Modern. При обновлении экспорта сверь эти секции с Figma. Для значений `rgba()` используй восьмизначный hex в конфигурации VS Code. Кастомные темы и пользовательские настройки цветов обрабатывает штатная служба тем Code OSS.

## Свойства Figma и слоты

- Имена с префиксом `_` обозначают внутренние свойства дизайна. Например, `_start` управляет видимостью иконки в макете, а `_iconOnly` задаёт вид варианта для сравнения в Figma. Публичный React API строится вокруг содержимого.
- `start` — слот `ReactNode`. В Figma в него подставляется экземпляр иконки, в React — узел с иконкой. Пустой слот скрывает иконку и связанный с ней зазор.
- Иконка в слоте наследует цвет текста. Для одноцветной SVG используй `fill="currentColor"` или `stroke="currentColor"` в зависимости от рисунка. Для SVG-файла с зафиксированным цветом используй его как альфа-маску, окрашенную в `currentColor`.

## Матрица TripleCode

**ActionButton** — [узел 138:6194](https://www.figma.com/design/H0WMYGGclEWe3lbjUabY3h/Triplecode-app?node-id=138-6194), [реализация](../extensions/triplecode-mvp/webview/design-system/components/action-button/action-button.tsx), [стили](../extensions/triplecode-mvp/webview/design-system/components/action-button/action-button.css).

| Свойство | Контракт TripleCode |
| --- | --- |
| `variant`, `size`, `rounding` | `ghost / filled`, `small / base / large`, `default / full` |
| `text`, `start` | Текст и ведущий слот `ReactNode`. Для кнопки с одной иконкой передай `text={null}`, `start` и `aria-label` |
| Состояния | Нативный `disabled`, клавиатурный фокус и взаимодействие браузера. `aria-pressed` для переключателей. `state` используется для фиксации вариантов в галерее |
| Темизация | Галерея использует палитру сравнения с Figma. Agent и нативные кнопки Workbench используют семантические переменные `--vscode-*` из каскада своей поверхности |

**ActivityBar** — [узел 183:6531](https://www.figma.com/design/H0WMYGGclEWe3lbjUabY3h/Triplecode-app?node-id=183-6531), [компонент](../extensions/triplecode-mvp/webview/design-system/components/activity-bar/activity-bar.tsx), [стили](../extensions/triplecode-mvp/webview/design-system/components/activity-bar/activity-bar.css). `children` принимает кнопки представлений, `ActivityBarButton` использует `ActionButton` и получает выбранное состояние от родителя. Стандартная кнопка 44 × 43 px, иконка 20 px, интервал 4 px. Высота панели определяется доступным пространством. В desktop те же стили подключены к нативным контролам Workbench с его командами, состояниями и компактным режимом.
