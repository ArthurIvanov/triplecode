# Чек-лист разработки компонента — Tripleform UI

> Справочник Tripleform UI. Для работы в TripleCode действуют [правила проекта](README.md).

При создании нового или доработке существующего компонента дизайн-системы Tripleform UI строго следуй приведённому ниже чек-листу. Отклонение от любого пункта без явного согласования с архитектором не допускается.

---

## 0. Перед стартом (pre-flight)

- [ ] Убедись, что компонент с таким названием и функцией **ещё не существует** в пакете — проверь `packages/react/src/components/`.
- [ ] Убедись, что в Figma **есть утверждённый макет** компонента. Работа без макета допускается только по явному поручению как технический компонент; тогда отсутствие макета фиксируется в предложении/аудите.
- [ ] Убедись, что все **необходимые семантические токены уже определены** в `foundation.css`. Если токена нет — согласуй его добавление до начала разработки (см. правила Figma MCP, раздел 5).
- [ ] Убедись, что тип изменений (новый компонент / доработка / breaking change) **согласован с архитектором** и определён тип Changeset (major / minor / patch).
- [ ] **Изолированный интерактивный предпросмотр вне проекта обязателен** до переноса в пакет — и для Figma-компонентов, и для технических без макета. Команда «делай» не отменяет этот шаг; перенос только после явного «добавляй» / «в проект».

## 1. Архитектура токенов и стилизация

- [ ] **Компонент не содержит «жёстких» значений** — цвета, отступы, размеры шрифтов и скругления задаются исключительно через `var(--...)`.
- [ ] **Используются только семантические функциональные токены** (`--bg-lead-loud-enabled`, `--fg-main`, `--gap-related`, `--padding-m`), а не примитивные (`--blue-500`, `--16`).
- [ ] **Не создаются новые компонентные токены** (типа `--button-primary-bg`). Компонент ссылается на общие семантические токены, соответствующие его роли.
- [ ] **Скругления и отступы** берутся из семантических алиасов (`--xs`…`--xl`, `--full`, `--gap-*`, `--padding-*`).
- [ ] **Все состояния** (`hover`, `active`, `disabled`, `loading`, `skeleton`, `focused`, ошибки) имеют соответствующие стили через токены состояний (`-hover`, `-active`, `-disabled`).
- [ ] **Тёмная тема** корректно работает без дополнительных переопределений — семантические токены переключаются автоматически.
- [ ] **Стили изолированы в CSS-модулях** (`*.module.css`), глобальные классы не протекают.

## 2. API компонента (пропсы)

- [ ] **Названия пропсов соответствуют матрице свойств Tripleform UI:**

    | Категория            | Проп                                                      | Тип                                                                                                                        |
    | -------------------- | --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
    | Семантический акцент | `appearance`                                              | `'primary' \| 'secondary' \| 'danger' \| 'success' \| 'warning' \| 'accent' \| 'neutral' \| 'info'`                        |
    | Визуальный стиль     | `variant`                                                 | `'filled' \| 'outlined' \| 'ghost' \| 'subtle' \| 'text' \| 'onLight' \| 'onDark' \| 'inverted' \| 'static'`               |
    | Размер               | `size`                                                    | `'extraSmall' \| 'small' \| 'base' \| 'large' \| 'extraLarge'` (якорь — `'base'`, `'medium'` не используется)              |
    | Состояния            | `disabled`, `loading`, `skeleton`                         | `boolean` (без префиксов `is`/`has`)                                                                                       |
    | Видимость            | `open`, `defaultOpen`                                     | `boolean` (controlled / uncontrolled для Modal, Popover, Dropdown)                                                         |
    | Ширина               | `fullWidth`, `width`, `minWidth`, `maxWidth`              | `boolean`, `string` (CSS)                                                                                                  |
    | Иконки               | `iconBefore`, `iconAfter`                                 | `string \| IconComponent` (имя из реестра или кастомный компонент)                                                         |
    | Слоты (атомарные)    | `elementLeft`, `elementRight`                             | `ReactNode \| ReactNode[]` (поддерживает массив; gap предустановлен)                                                       |
    | Слоты (составные)    | `contentLeft`, `contentRight`                             | `ReactNode`                                                                                                                |
    | Текст                | `text`                                                    | `string` (кнопки, бейджи)                                                                                                  |
    | Счётчик              | `count`                                                   | `number` (Badge, Tag, Chip, Tab; отображается как `99+`)                                                                   |
    | Метка поля           | `label`                                                   | `string` (поля ввода)                                                                                                      |
    | Цвет текста          | `color`                                                   | `'primary' \| 'secondary' \| 'muted' \| 'disabled'` (Text, Heading, Label, Caption; маппится на fr-токены)                 |
    | Валидация            | `validationStatus`, `validationMessage`                   | `'default' \| 'success' \| 'error' \| 'warning' \| 'info'`, `string`                                                       |
    | Статус уведомлений   | `status`                                                  | `'info' \| 'success' \| 'warning' \| 'error'`                                                                              |
    | Ориентация           | `orientation`                                             | `'horizontal' \| 'vertical'`                                                                                               |
    | Позиционирование     | `placement`                                               | `'top-left' \| 'top-center' \| 'top-right' \| 'bottom-left' \| 'bottom-center' \| 'bottom-right' \| 'left-*' \| 'right-*'` |
    | Адаптивность         | `breakpoint`                                              | `'xs' \| 'sm' \| 'md' \| 'lg' \| 'xl'`                                                                                     |
    | Перенос строк        | `wrap`                                                    | `boolean` (ButtonGroup, Stack, Flex)                                                                                       |
    | Зазоры               | `gap`, `rowGap`, `columnGap`                              | только именованные значения (`'noGap' \| 'closest' \| …`), произвольный `string` запрещён                                  |
    | Отступы              | `paddings`, `paddingTop/Right/Bottom/Left`, `paddingSize` | `boolean`; `paddingSize` — именованные значения                                                                            |
    | A11y-метки           | `aria-label`, `aria-labelledby`, `aria-describedby`       | `string` (обязательны в соответствующих контекстах)                                                                        |
    | Идентификатор        | `id`                                                      | `string` (обязателен для связи label ↔ input, aria-describedby)                                                            |
    | Содержимое           | `children`                                                | `ReactNode` (если компонент — контейнер)                                                                                   |

- [ ] Проп `error` **не используется** — заменён на `validationStatus` + `validationMessage`.
- [ ] **Компонент поддерживает `forwardRef`** и корректно передаёт реф на корневой DOM-элемент.
- [ ] **Пробрасываются стандартные HTML-атрибуты** (`...rest`): `className`, `style`, `aria-*`, `data-*`. Компонент не удаляет и не игнорирует переданные a11y-пропсы.
- [ ] **Полиморфизм** (если применимо): реализована поддержка `as` или `asChild` для смены корневого элемента с сохранением доступности.
- [ ] **Типы пропсов экспортируются** из `types.ts` (например, `ButtonProps`) и реэкспортируются через `index.ts`.

## 3. Семантический HTML и доступность (a11y)

- [ ] **Корневой элемент — семантически правильный:** кнопка → `<button>`, поле → `<input type="...">`, модалка → `<dialog>`. `<div>` с ARIA-ролью допустим только при невозможности использовать семантический тег.
- [ ] **Интерактивные элементы управляются с клавиатуры:**
    - Активация — <kbd>Enter</kbd> и <kbd>Space</kbd>.
    - Закрытие — <kbd>Escape</kbd> (модалки, поповеры, дропдауны).
    - Навигация стрелками в группах, табах, меню.
- [ ] **Фокус:** нет положительного `tabIndex`; ловушка фокуса в модалках; фокус возвращается на триггер при закрытии.
- [ ] **Индикатор фокуса** (`:focus-visible`) не удалён и не скрыт без крайней необходимости.
- [ ] **Состояния отражены в ARIA:**
    - `disabled` → `aria-disabled="true"`.
    - `loading` → `aria-busy="true"`.
    - `validationStatus="error"` → `aria-invalid="true"` + `aria-describedby` на элемент с сообщением.
    - `required` → `aria-required="true"`.
    - Раскрытие → `aria-expanded`; связь с управляемым элементом → `aria-controls`.
- [ ] **Динамический контент** (тосты, алерты, результаты валидации) объявляется через `role="alert"` или `aria-live="polite"` в зависимости от срочности.
- [ ] **Связь с метками:** поля формы используют `<label htmlFor>`. Если метка скрыта — `aria-label` или `aria-labelledby`. Группы радиокнопок и чекбоксов — `<fieldset>` + `<legend>`.
- [ ] **Иконки:**
    - Декоративные → `aria-hidden="true"`, `focusable="false"`.
    - Значимые → обязателен проп `label` (добавляет `role="img"` и `aria-label`).
- [ ] **Цвета не являются единственным носителем информации** (ошибка = иконка + текст + цвет границы).
- [ ] **`prefers-reduced-motion: reduce`** учтён — анимации отключаются или заменяются мгновенными изменениями.

## 4. Структура файлов и документация

- [ ] Компонент размещён в `packages/react/src/components/ComponentName/`.
- [ ] Файловая структура:

    ```
    ComponentName/
    ├── ComponentName.tsx          # реализация
    ├── ComponentName.module.css   # стили
    ├── ComponentName.test.tsx     # тесты
    ├── ComponentName.stories.tsx  # истории Storybook
    ├── types.ts                   # экспорт типов пропсов
    └── index.ts                   # реэкспорт компонента и типов
    ```

- [ ] **JSDoc-комментарии** для всех пропсов: описание, тип, значение по умолчанию.
- [ ] **Storybook:**
    - Истории для каждого варианта (`appearance`, `variant`, `size`).
    - Состояния: `enabled`, `hover`, `focus`, `disabled`, `loading`, `skeleton`.
    - Истории для `open` / `defaultOpen` у компонентов с контролируемой видимостью.
    - Истории для ошибок валидации (если применимо).
    - Параметр `figma` со ссылкой на узел макета (если есть).
    - Включена вкладка Accessibility (`@storybook/addon-a11y`) и проверяется для каждой истории.

## 5. Тестирование

- [ ] **Unit-тесты** (Vitest + Testing Library):
    - Рендеринг с разными пропсами.
    - Вызов колбэков (`onClick`, `onChange` и т.д.).
    - Корректная передача рефа через `forwardRef`.
    - Наличие и содержимое ключевых DOM-атрибутов (`aria-*`, `data-*`).
- [ ] **Snapshot-тесты** — для стабильных компонентов без сложной логики, чтобы фиксировать структуру разметки.
- [ ] **Тесты доступности** с `vitest-axe`: запускаются на каждом интерактивном компоненте, проверяют отсутствие критических нарушений axe-core.
- [ ] **Визуальные регрессионные тесты** (Chromatic) — настроены в CI, запускаются при PR.
- [ ] Все тесты проходят локально и в CI.
